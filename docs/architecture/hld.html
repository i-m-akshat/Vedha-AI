Vedha AI — System High-Level Design

A complete, intuitive, and production-grade architectural blueprint of Vedha AI: explaining how the React SPA, Chrome Extension, ASP.NET Core 10 backend, Crawl4AI scraping sidecar, and truth-preserving ATS engine work together seamlessly.

01. System Overview & The Core Problem

Vedha AI is an enterprise AI Career Operating System. In today’s competitive job market, candidates face two major challenges:

📄
Problem 1: ATS Screening Black Boxes

Applicant Tracking Systems (Workday, Greenhouse, Taleo) automatically reject up to 75% of qualified resumes because candidate achievements lack exact semantic keywords or use multi-column formatting that ATS parsers fail to read.

🤖
Problem 2: Hallucinating AI Tools

Existing AI resume tailors frequently invent fake employers, fabricate false metrics (turning a $50K project into a $5M claim), or corrupt work experience dates, putting candidates at risk of failing background verification checks.

💡 Human-First Explanation: What Does Vedha AI Actually Do?

Think of Vedha AI like a senior executive recruiter and fact-checker working for you. You upload your genuine Master Resume once. When you find an exciting job on LinkedIn or any website, Vedha AI reads the job requirements, aligns your real achievements to match the exact vocabulary the ATS wants, checks that not a single fake fact or number was invented, and formats it into a 95%+ ATS-compatible resume. Meanwhile, the Chrome Extension stays right beside you on job portals, auto-filling contact fields and employer screening questions from your verified profile. If a question cannot be grounded, it is outlined for you to review instead of being guessed.

1. Single Source of Truth

Candidate uploads a master resume (PDF/DOCX/MD). All skills, metrics, and roles are extracted and protected.

2. Truth-Preserved Tailoring

The AI tunes bullets to match the target job description while strictly enforcing quantitative metric invariants.

3. Autonomous Copilot

Manifest V3 browser extension bridges authentication, performs LinkedIn auto-applies, and matches requirements live.

03. Software Architecture (Clean Architecture & CQRS)

The backend is strictly organized into four concentric Clean Architecture layers. Business rules never depend on external databases or UI frameworks; dependencies always point inward.

🎯
1. Domain Layer (`ResumeTailor.Domain`)

The innermost core. Contains pure C# domain entities (User, MasterResume, GeneratedResume, JobDescription), Value Objects (ResumeSchema, WorkExperienceItem), and the deterministic ExperienceChronologyHelper. Zero NuGet dependencies.

⚡
2. Application Layer (`ResumeTailor.Application`)

Coordinates business use cases using CQRS and MediatR. Handlers execute distinct workflows (e.g. GenerateTailoredResumeCommand, ParseRawJobDescriptionCommand). Defines application interfaces without knowing their concrete implementations.

🔌
3. Infrastructure Layer (`ResumeTailor.Infrastructure`)

Implements the application contracts: Entity Framework Core DbContext with PostgreSQL, S3 storage client, QuestPDF document generator, AtsScoringEngine, and AI providers (Gemini, Claude, OpenAI).

🌐
4. Web API Layer (`ResumeTailor.WebApi`)

ASP.NET Core 10 Web API. Handles HTTP routing, JWT token extraction, SignalR real-time hubs (TailoringProgressHub), and global RFC 7807 exception translation.

💡 Human-First Explanation: Why Clean Architecture?

Imagine building a high-performance sports car where the engine, wheels, and navigation screen can be replaced without rewriting the chassis. In Vedha AI, if we want to switch the database from PostgreSQL to another system, or change from Gemini to Claude, we only change a single class in the Infrastructure layer. The core resume-tailoring logic and ATS rules never break.

04. Frontend Architecture & Minimalist Design System

The web frontend is a single-page application built with React 19, TypeScript, and Tailwind CSS, bundled via Vite.

Minimalist & Aesthetic

Replaced futuristic, overwhelming dashboard clutter with a refined, human-first visual style inspired by Linear, Stripe, and Apple.

Single-Logo System

Light mode uses vedha-logo.png. Dark mode uses VedhaAI-Dark.png. Clean, uncluttered header with no redundant title text.

Zustand State Stores

Lightweight reactive state stores (useTailorStore, useAuthStore) managing session state, tailored diffs, and live progress.

Key Pages & User Studios

  • Master Resume Studio (MasterResumePage.tsx): Upload documents, auto-parse into structured fields, toggle current employment, and edit STAR bullet points.
  • Tailor Studio (TailorStudioPage.tsx): Input job posting URLs or text, preview real-time progress, and view side-by-side bullet diffs highlighting matching keywords.
  • Result & Export Studio (ResultStudioPage.tsx): Review ATS scorecards, recruiter feedback, and download ATS-compliant PDF, Word, or Markdown files.
  • Application Tracker (TrackerPage.tsx): Kanban board tracking saved, applied, interviewing, and offer states.

05. Chrome Extension Copilot & Token Bridging

The Chrome Extension (Manifest V3) acts as the candidate’s autonomous browser copilot directly on job platforms like LinkedIn, Greenhouse, and Lever.

💡 Cross-Context Authentication Bridge

Normally, browser extensions cannot read localStorage from websites. When you log in on http://localhost:3000, our web app emits a secure VEDHA_AUTH_TOKEN_SYNC event. The Vedha content script catches this event and transfers the token into chrome.storage.local. You log in once, and your extension is immediately unlocked!

06. Truth-Preserving ATS Optimization Engine

The ATS engine solves the critical problem of AI hallucination through rigorous mathematical and programmatic invariants implemented in AtsScoringEngine.cs.

1. Quantitative Metric Invariant

A regex extraction engine parses all numbers, percentages (%), dollar amounts ($), and multipliers (3x). Any tailored bullet claiming a metric not present in the master resume triggers an immediate truth violation.

2. Entity Verification Check

The engine checks that every company name, university, and certification in the generated resume exists in the verified master resume. Unauthorized entities cause automatic rollback.

Experience Chronology Rule (Present Employment Always First)

Under ADR-003, the engine deterministically ensures that Present / Current Employment (where isCurrent == true or endDate is "Present") is ALWAYS placed at the top of the experience list. Older roles can never overtake current employment based on keyword density.

Ultra-fast HTML parser fallback for lightweight, static career portals.

08. Database, Vector Embeddings & Object Storage

Vedha AI separates structured metadata, vector embeddings, high-speed caches, and large document binaries into dedicated storage engines:

🗄️
PostgreSQL 16 + pgvector

Stores transactional entities (Users, MasterResumes, GeneratedResumes, Applications). Uses pgvector to store high-dimensional embeddings of candidate achievements and job responsibilities for sub-second semantic retrieval.

📦
MinIO S3 Object Store

Self-hosted S3-compatible storage. Houses rendered PDF resumes, DOCX files, and raw uploaded master documents. Downloads are served via secure time-limited SigV4 pre-signed URLs.

09. End-to-End User Journeys & Sequence Flows

A
Master Resume Onboarding

Candidate uploads PDF/Word document -> Local text extractors (PdfPig/OpenXml) or Multimodal AI parse structure -> Normalizes dates and sorts present employment first -> Persists in PostgreSQL and creates Version 1 snapshot.

B
Target Job Tailoring

Candidate pastes Job URL -> Crawl4AI scrapes clean Markdown -> LLM extracts structured JD schema -> Tailoring engine optimizes bullets, retaining 80%+ quantitative metrics -> ATS scoring engine verifies truthfulness -> Candidate downloads PDF.

C
Chrome Extension Quick Apply

Candidate opens LinkedIn job -> Extension grabs page DOM -> Calls /api/orchestrator/quick-match -> Live Match Scorecard displays in sidepanel -> Generates tailored cover letter with one click.

11. Security, Privacy & Operational Resilience

🛡️
Token Security & Zero Secret Leaks

JWT secrets and API keys are stored strictly in environment variables. .env files are ignored by git. S3 buckets use least-privilege policies.

🔄
Self-Healing & Local Fallbacks

If AI provider keys fail, local extraction (PdfPig/OpenXml) continues to function. If Crawl4AI times out, AngleSharp and direct paste ensure zero user blockers.
