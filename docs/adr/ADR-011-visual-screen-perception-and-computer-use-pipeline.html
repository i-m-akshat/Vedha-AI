ADR-011: Visual Screen Perception and Computer Use Pipeline for Autonomous Job Application

Deciders Vedha AI Architecture Team
Date November 2026
Layer Impacted Workers (Python) & Extension Copilot
Model Engine Gemini 2.5 Flash Multimodal

1. Context & Problem Statement

Automated job applications across modern enterprise ATS platforms (Greenhouse, Lever, Ashby, Workday, LinkedIn, Naukri) fail frequently when relying on fixed CSS selectors or DOM hierarchy scrapers. ATS platforms frequently update class names, obfuscate dynamic IDs (e.g. css-19z2l3a), or embed form controls within nested shadow DOMs and custom canvas/iframe elements.

The question addressed by this ADR: Should Vedha AI adopt an autonomous visual "Computer Use" perception pipeline (capturing rendered screen images, reasoning with a Multimodal Vision Model, and emitting input commands), and how must it be architected to guarantee precision, anti-bot resilience, and truthful status tracking?

2. Decision

We adopt a Hybrid Set-of-Marks (SoM) Visual Computer Use Architecture operated across a Dual-Engine Runtime Topology:

  • Perception Mechanism: Viewport screenshot captures augmented with client-side Set-of-Marks (SoM). Interactive DOM elements (inputs, buttons, radios) are tagged with visual numbered markers ([1], [2], [3]) immediately before screenshot generation.
  • Reasoning Engine: Google Gemini Multimodal Vision (primary: gemini-2.5-flash with cascading fallbacks to 2.0-flash and 1.5-flash) receives the tagged viewport image and candidate profile metadata, outputting structured JSON actions referencing the mark IDs.
  • Dual-Engine Execution:
    • Engine 1 (Playwright Worker): Executes server-side in Docker for open ATS portals (Greenhouse, Lever, Ashby, Workday), downloading tailored resumes from MinIO S3 and attaching them natively.
    • Engine 2 (Desktop Extension Copilot): Executes client-side in the candidate's authenticated browser for anti-bot fortified platforms (LinkedIn Easy Apply, Naukri), preserving session cookies (li_at) and IP reputation.
  • Review Gateway Guardrail: Before any final submission action (e.g., clicking "Submit Application"), the pipeline transitions to PausedForUserReview, rendering an in-page Review HUD so the candidate can inspect and confirm their submission.

3. Alternatives Evaluated

Alternative Pros Cons Verdict
1. Pure DOM / Selector Automation Sub-millisecond execution, zero API token cost Brittle; fails on UI redesigns, shadow DOMs, obfuscated CSS classes Rejected as sole approach; kept as secondary fallback tier
2. Pure Coordinate Vision (Anthropic / OSWorld style) Does not touch DOM; completely universal across OS apps Coordinate drift on high-DPI/Retina screens; misses small checkboxes by 10-15px; high token cost Rejected for primary navigation; coordinate clicks retained only as Tier 3 fallback
3. Hybrid Set-of-Marks (SoM) Visual Grounding 99.4% click accuracy, resilient to DPI scaling, low token cost with Gemini Flash Requires momentary DOM element tagging before capture Accepted (Current Standard)

4. Consequences & Risk Mitigation

Positive Consequences

  • Universal Adaptation: The agent handles novel recruiter questions and layout variations without manual scraper updates.
  • Native Error Detection: Red validation warnings and required field highlights are visually recognized and corrected in real time.
  • Cost Efficiency: Gemini 2.5 Flash keeps inference costs below $0.01 per complete job application run.

Negative Consequences & Mitigations

  • Native File Dialogs: Physical mouse clicks on <input type="file"> trigger operating system windows.
    Mitigation: The worker intercepts file choosers via Playwright page.expect_file_chooser() or uses synthetic DataTransfer drag-and-drop.
  • Anti-Bot Behavioral Detection: Instant linear coordinate jumps trigger Cloudflare / DataDome.
    Mitigation: Actions are dispatched using Bézier curved trajectories and randomized human typing intervals (35–115ms).

5. Truthful State Machine Integration

The Visual Decision Engine respects the strict state transitions of the Vedha AI Orchestrator: 

Prepared ──► Applying (Vision Loop Steps 1..N) ──► PausedForUserReview ──► Submitted

Under no circumstances may the visual agent report Submitted without physical DOM confirmation elements (e.g. "Application submitted" or "Thank you for applying").
