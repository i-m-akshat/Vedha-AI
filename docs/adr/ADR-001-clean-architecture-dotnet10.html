Clean Architecture with CQRS & ASP.NET Core 10

💡 Plain-English Summary: Why Does This Matter?

Building enterprise software without clear layers is like building a house where plumbing, wiring, and wall paint are tangled together. If you want to change the sink, the roof collapses. With Clean Architecture, our business logic (how resumes are parsed and tailored) lives in an independent bubble that never touches databases or web controllers directly. We can change our database, our AI provider, or our web framework at any time with zero fear of breaking the resume builder.

1. Context & The Problem

Vedha AI handles complex, high-stakes tasks: multimodal document parsing, AI model calls (Gemini, Claude, OpenAI), ATS keyword scoring, and browser automation. Without strict layer boundaries, code quickly degenerates into giant "Service" classes that mix database queries, AI prompt calls, and HTTP responses, making automated testing nearly impossible.

Concentric Clean Architecture Layers (Dependencies Point Inward)

2. The Decision

We adopted Clean Architecture with CQRS (MediatR) in ASP.NET Core 10 (.NET 10) across four isolated projects:

  • ResumeTailor.Domain: Pure C# business models (User, MasterResume, GeneratedResume, ResumeSchema). Zero external NuGet dependencies.
  • ResumeTailor.Application: CQRS Commands and Queries. Mediates use cases and defines interfaces (IAiProvider, IS3StorageService, IAtsScoringEngine).
  • ResumeTailor.Infrastructure: Implements all interfaces. Connects PostgreSQL 16 + pgvector, MinIO, NATS JetStream, and AI SDKs.
  • ResumeTailor.WebApi: Thin API surface handling routing, authentication tokens, and SignalR hub streaming.

3. Alternatives Considered

Option A: Flat 3-Tier Layering

Rejected: Causes "God Objects" where a single ResumeService exceeds 3,000 lines, mixing database queries with prompt engineering and business logic.

Option B: Clean Architecture + CQRS

Selected: Each business operation has a single, small command handler. Can be thoroughly unit-tested in under 5 seconds without database mocks.

4. Consequences & Benefits

  • 55+ Passing Unit Tests: Business logic runs instantly in in-memory test suites.
  • Multi-Provider Freedom: Switching from Gemini to OpenAI or Claude takes 1 line of configuration.
  • Zero Framework Lock-In: The core domain entities remain pure C# code forever.
