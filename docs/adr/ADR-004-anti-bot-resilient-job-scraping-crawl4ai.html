ADR-004 ACCEPTED 2026-09-28

Hybrid Anti-Bot Scraping Pipeline via Crawl4AI Sidecar & Playwright Fallback

💡 Plain-English Summary: Why Does This Matter?

When you paste a job link from LinkedIn, Greenhouse, or Workday into Vedha AI, most simple web downloaders fail completely. Why? Modern websites are guarded by anti-bot walls (Cloudflare CAPTCHAs) and build their pages with JavaScript that requires a real browser engine to render. If a simple bot asks for the page, it gets an empty white screen or a "403 Forbidden" error. We built a specialized web intelligence robot (Crawl4AI) that runs inside its own Docker container, looks exactly like a real human clicking through a browser, unrolls hidden "Show more" buttons, and extracts the full job description cleanly into readable Markdown.

1. Context & The Problem

Accurate resume tailoring requires obtaining the full, unadulterated Job Description (JD). When candidates submit job URLs, three major failure modes affect naive HTTP scrapers:

  • Anti-Bot Fingerprinting: Cloudflare, DataDome, and Akamai challenge bare HTTP clients, returning 403 Forbidden responses.
  • Client-Side Rendering (SPA): Modern ATS platforms (Workday, SmartRecruiters) dynamically hydrate page content via React/Angular after DOM load.
  • Truncated Descriptions: Job requirements are hidden behind interactive accordions (e.g., "Show more", "See full description").

2. The Architectural Decision

We architected a 3-tier resilient fallback scraping pipeline:

  • Tier 1 — Crawl4AI Dedicated Docker Container (vedha-crawler:11235): A dedicated container running Crawl4AI (Python + Playwright + human fingerprint spoofing). It waits for DOM network idle, automatically runs a JavaScript accordion-click script to unroll truncated job text, strips scripts/ads/headers, and streams back pristine Markdown directly to the backend.
  • Tier 2 — Asynchronous Playwright Worker Pool: If the sidecar is unreachable or times out after 15 seconds, the request is published to a NATS JetStream queue (crawler.jobs) where local Playwright workers execute isolated headless browser sessions.
  • Tier 3 — Static AngleSharp / HttpClient: For simple blogs, static HTML career portals, or developer test environments where headless browsers are unnecessary.
  • LLM Schema Normalization: Once clean markdown is acquired, an LLM prompt extracts a deterministic JSON schema containing Job Title, Company, Seniority, Required Skills, Nice-to-Have Skills, and Tech Stack tags.

3. Alternatives Evaluated

❌ Third-Party Paid Scraping APIs

Commercial scraping proxies (e.g. ScrapingBee, Zyte) charge steep recurring monthly fees per URL and transmit candidate URLs and job data to third-party data brokers.

❌ Basic HttpClient + HtmlAgilityPack

Lightweight and requires no containers, but fails on >80% of modern corporate career sites due to Cloudflare anti-bot blocks and React client-side rendering.

4. Role versus company motto

Career sites put the company and its motto in the document title and the first heading (Acme — We help teams ship faster). That string is not the job. After either scraper returns, JobPostingTitleParser keeps a segment only when it looks like a role (Engineer, Manager, Director, and the same family of words). Motto sentences are dropped. The real role is read from a later heading or a Job Title: line. Locations after at Company are not stored as the company name.

5. Consequences & Impact

  • High Reliability: Reaches over 95% extraction success across LinkedIn, Workday, Lever, and Greenhouse.
  • Zero API Costs: 100% self-hosted in our local Docker environment.
  • Container Isolation: Heavy browser memory usage is contained inside the vedha-crawler container, keeping the ASP.NET Core API server lean and lightning-fast.
