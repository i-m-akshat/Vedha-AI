ADR-002 ACCEPTED 2026-09-18

Dual-Layer Auth & Cross-Context Extension Token Bridging

💡 Plain-English Summary: Why Does This Matter?

Imagine you log in to Netflix on your laptop. You expect the Netflix extension or mobile companion app to know who you are without asking you to type your password again or copy-paste ugly secret codes. In Chrome, the browser strictly separates website memory from browser extension memory for security. We created a safe digital handshake: when you log in to Vedha AI, our web app securely taps our extension on the shoulder, shares your verified access pass, and powers up your job auto-filler immediately.

1. Context & The Problem

Vedha AI operates on two distinct browser surfaces:

  • Web Application: React SPA running on http://localhost:3000 or https://vedha.ai.
  • Chrome Extension: Manifest V3 extension running isolated background workers, popup dialogs, and content scripts on third-party job boards (e.g., linkedin.com).

Under Chrome's sandbox security model, the extension popup and background service workers are physically prohibited from reading localStorage or session tokens belonging to the web app's domain. Furthermore, standard third-party cookies are blocked by modern privacy protections. Without a dedicated communication bridge, users would be forced to log in twice or manually paste JWT tokens.

2. The Architectural Decision

We engineered a five-step decoupled token bridge:

  • 1. Web App Token Storage: Upon standard authentication or registration, the web app stores the JWT in localStorage under vedha_token.
  • 2. PostMessage Handshake Broadcast: The React app fires a targeted DOM message: window.postMessage({ type: 'VEDHA_AUTH_TOKEN_SYNC', token, user }, window.location.origin). Specifying the target origin ensures other tabs or cross-origin scripts cannot intercept the payload.
  • 3. Injected Relay Script: The extension Manifest injects a tiny, dedicated content script matching the web host origin (localhost:3000/* or https://vedha.ai/*). It listens specifically for VEDHA_AUTH_TOKEN_SYNC and immediately forwards the payload to the background service worker via chrome.runtime.sendMessage({ action: 'SET_TOKEN', ... }).
  • 4. Isolated Storage: The background worker persists the session securely in chrome.storage.local. From this moment on, all extension views (Sidepanel, Popup, and LinkedIn Content Scripts) can instantly pull the candidate's master resume details and verified JWT.
  • 5. Graceful Unauthenticated State: If the user opens the extension before logging in, the extension detects the empty storage and presents a clean "Connect Vedha AI" card with a 1-click button opening the login page. As soon as they sign in, the bridge fires automatically and refreshes the extension.

3. Alternatives Evaluated

❌ Chrome Identity API (WebAuthFlow)

Works well for pure OAuth2 providers (Google/GitHub), but severely complicates local email/password testing, self-hosted deployments, and offline staging environments.

❌ Third-Party Cookie Sharing

Severely restricted by Chrome Privacy Sandbox and third-party cookie phaseouts. Unreliable on external domains like LinkedIn.

4. Consequences & Impact

  • Zero Friction User Experience: Log in once in your browser; your extension is automatically connected and ready to apply for jobs.
  • Strict Security Compliance: Obeys Manifest V3 isolation standards without granting blanket host permissions or dangerous web-accessible resources.
  • Synchronized Logout: Logging out from the web app sends a corresponding clear message that purges tokens from chrome.storage.local simultaneously.
